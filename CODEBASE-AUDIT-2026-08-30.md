## 6. Summary

**Production-ready (with caveats)**
- Build/type/lint/test hygiene is excellent: `tsc` clean, ESLint 0 warnings/0 errors, **882 unit tests pass**, CI has a comprehensive 14-step pipeline (build, SEO smoke, security, ops, release, provisioning, Storybook, a11y, perf).
- Search query parsing/faceting (`parse-query.ts`, `facets.ts`, `filters.ts`) is thoughtfully designed with a shared predicate between client and server, a zero-result relaxation ladder, and honest pagination caps.
- The public **read-only, fixture-backed** site (Home, city hubs, locality pages, listing dossiers, guides, price index, compare) is coherent, accessible, SEO-tagged, and fully rendered without JS (sitemaps/robots/indexing gates, JSON-LD, no-JS smoke tests).
- The **in-memory demo workflows** work end-to-end: leads (masked + idempotent), broker drafts, moderation + publish gate, media packets, saved searches, requirements, authority registry.
- Secrets handling is genuinely careful: no hardcoded credentials found; a hygiene allow-list, redacted pino logger, and secret-scan scripts exist.
- The codebase is unusually well-documented: most "problems" have a written rationale and a test; the self-audit culture is a real asset.

**Partially done**
- **Auth**: only the demo session works. `better-auth` mode is configuration-complete but returns `session: null` always (I-1). Broker/admin surfaces are effectively demo-only; they 401/503 in any real deployment.
- **Data source switch**: `ARCHITECH_DATA_SOURCE=prisma` is real for `/api/search`, leads, saved searches, and broker/media writes — but the entire **public site still renders fixtures** (M-1). A production deploy would show demo inventory while the DB holds nothing.
- **Media**: contract + moderation + retention policy exist, but R2 signing is a placeholder, derivatives/EXIF are claimed-not-done, and retention isn't enforced (I-3, B-17, M-6).
- **Search**: Prisma mode works for small scopes, but the advertised Postgres FTS/trigram plan is never executed (I-7), nationwide results silently cap at 5000 (B-13), and the `searchVector` column is missing from `schema.prisma` (B-15).
- **Observability**: health/errors/web-vitals endpoints exist; WebVitals reporter isn't mounted (M-3) and SLO values are hardcoded placeholders (I-4). Sentry client deliberately off.
- **SEO OS**: sitemaps/robots/gates/discovery spine are well-built, but the spine and canonicalization only work inside a single Node process; canonicalization is recorded but never acted on (B-2), and all of it is fixture-driven.
- **Admin/agent UI**: moderation queue and acquisition queue are wired; most of AgentWorkspace is placeholder shell (I-6).

**Broken or missing entirely**
- **Production auth** (I-1) — the platform cannot authenticate a real user; all protected APIs are unusable in production.
- **Canonicalization/duplicate-dedup logic** (B-1, B-2, B-18) — gate bypass on duplicate + no actual canonical redirect; duplicate peers only in-memory.
- **R2 media upload** (I-3) — "enabled" mode returns a fake signed URL; uploads go nowhere.
- **Authority registry in Prisma mode** (B-8) — writes audit events only, loses data on restart.
- **Static `pnpm start` deploy** (I-10, C-7) — Railway target has no API and a false-green healthcheck.
- **Notification pipeline** (M-7) — saved-search `notify` and lead follow-ups are stored but never sent; `RESEND_API_KEY` unused.
- **External AI provider** (I-2) — no provider exists.
- **Public-site Prisma reads** (M-1) — the largest single gap: switching to `prisma` data source doesn't change what buyers see.

### Top 10 fixes, in order
1. Wire live Better Auth session resolution (I-1) or gate production behind a hard "auth incomplete" build failure.
2. Connect public pages/SEO registry to `*ForServer` reads (M-1) — make `ARCHITECH_DATA_SOURCE=prisma` actually change what's rendered.
3. Fix publish-gate canonicalize-vs-block ordering and implement real canonical redirects (B-1, B-2, B-18).
4. Validate moderation `decision` (B-4) + add unique-draft collision handling (B-3).
5. Implement real R2 presigning or disable R2 mode (I-3, C-10).
6. Add `searchVector` to `schema.prisma` and execute (or remove) the Postgres search plan (I-7, B-15).
7. Fix saved-search validation/dedupe and 404-vs-500 delete (B-7).
8. Persist authority registry rows in Prisma mode (B-8) or remove the mode.
9. Mount `WebVitalsReporter` and feed real SLO values (M-3, I-4).
10. Sync env templates/allow-list with actual runtime keys (C-1, C-2) and fix `frame-ancestors`/sandbox origin config (C-5).
